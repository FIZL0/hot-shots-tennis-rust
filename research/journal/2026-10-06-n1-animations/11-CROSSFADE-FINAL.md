# N1e — motion crossfade (FINAL)
- Code: `hst-sim::motion` (`Fade` with start/tick/tick_hold, `mix`), `crates/hst/src/character.rs` (wired into the player update). Tests in `crates/hst-sim/tests/motion.rs`: `anim_s05_fade` and `fade_mix_ram`.
- Motion object fade fields: +0x44 old id, +0x48 old clip, +0x4c old sampled time, +0x50 old time, +0x54 old speed, +0x58 old loop, +0x5c frames, +0x60 countdown, +0x64 weight, +0x6c hold flag, +0x70 blend track count (23, set at player init), +0x74 special track (-1, or 6 for stand<->ready 1<->2; 1->2 only when player +0x12bc == 10).
- Setter rules: a looping motion that is already playing returns early, otherwise it fades 8 frames. For non-looping motions, 0x1c/0x1d are a held fade with frames = the caller's hold + 1, 0x27/0x28 fade 8 frames, and anything else cuts. At a point's end the game resets first (motion -1, no clip, so a cut) and then sets.
- Start: if frames < 2, cut. With no old clip, take the current motion (id, clip, time, speed, loop) and set count = frames-1. With an old clip (a switch mid-fade), let f = count/oldframes. If f > 0.5 and the old id != the new id, cut. Otherwise take the current motion and set count = trunc(madd(0.5, f>=0.5 ? f : 1-f, frames)), then count -= 1. The weight is count/frames. In hold mode, time -= speed and weight = 1 - count/frames. Then sampled = time.
- Per frame, normal path: sample and advance the new motion. For the old motion, wrap its time to its own length/loop, sample it, mix it with the weight from before the step, then time += speed. Then count -= 1; if count < 0, clear the old motion, else weight = count/frames.
- Per frame, hold path: the old clip is sampled fully (a frozen pose). After the player update, the new clip at time 0 is mixed over the current matrices with the weight, for tracks < 23. Then count -= 1; when count < 0 the hold ends and the new clock starts advancing.
- Mix per track k < 23: the rotation is a shortest-arc slerp(cur, other, w) and the position is madd(add(0, cur), sub(other, cur), w). Single-key tracks are blended too. The special track uses a longest-arc slerp and a different to-matrix.
- Result: state machine bit-exact vs the anim_s05 fixture (35283 frames, 3076 fading, 713 sets of which 10 are held and 121 mid-fade, 0 missed). Per-bone mix bit-exact vs RAM (3 players mid-fade in s04/s08/s09, 69 tracks).
- Not done (ponytail): the special track 6 longest-arc slerp is not ported; unkeyed base tracks mix from the rest pose where the game uses stale node values; the hold mix is applied before the arm IK (the game applies it after the update); no sub-frame interpolation of the overlay.
