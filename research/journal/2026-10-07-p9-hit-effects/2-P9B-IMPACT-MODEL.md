# P9b — racket impact model in the app

- `crates/hst/src/effects.rs`: loads the six `yumoto/impact_{top,slice,flat,lob,drop,smash}_a` models (mdl/mtl/mti/ani/mor/mta) from `AZUMA/C_EFF/EFFCT.XB0`. Each one is a skinned model whose joints are its ANI nodes, with morph weights from `.MOR` and per-material alpha from `.MTA`, all driven by `hst_sim::effect::Effect`. Materials are unlit and double-sided; `@add` names use additive blending, everything else uses normal blending.
- Which model plays: a smash (class 3 in strike, branch 4 in the game) uses model 5, otherwise the shot kind does. Scale uses the shot kind even for a smash, so a smash of kind 1/3/4 stays at 1 (P9a). The game has one impact object, so a new hit restarts whichever model it picks and hides the one that was playing.
- Timing: `strike` hands the hit to the `start_effects` system, which runs after `simulate` in the same FixedUpdate frame. `effects::tick` runs at the top of the next frame, so the first live frame is time 0 → 1, as the P9a test shows. The world matrix comes from `impact_matrix(vel, ball pos)`, the scale from `impact_scale`, and both are fixed at the start.
- Check: `HST_AUTOPLAY=1 hst <iso> --play --shot … --shot-at 4.45` / `17.82` (3 frames after a flat and a lob in the seeded rally) next to PCSX2 slot 5 captured the moment `imp+0x50` turned 1 (context/shots/p9/). The port's flat is a blue additive starburst and its lob a green ring; the game's topspin serve is a purple starburst. All sit on the ball, sized about like a player's head to upper body. Port scales were 0.92–1.46 (top/flat), the same range as the recorded game impacts. The game's lob/flat frames were grabbed late (the effect is only 12–15 frames long), so the starburst is the clearest comparison.
- Not checked: node matrices against the game (the ANIs are close to static) and pixel colours (screenshot lag). A plain screen grab can't time an effect frame-exactly; the bit-exact checks live in the hst-sim test.
