# C2 — readable PS2 float math

Done in C2: `ps2::F` (EE FPU) and `vu0::Vf` (VU0 lane) newtypes, `ball.rs` · `shot.rs` · `player.rs` converted,
the float lint on every module with no float math, `crates/hst-sim/tests/float_math.rs` (lists what is left) and a
clippy step in `tools/done.sh`. The rest of `hst-sim/src/` is split into the follow-up tasks C4…C8; each converts
its modules the same way. Journal: `research/journal/2026-10-14-c2-readable-float/`.

## How to convert a module

- Import `use crate::ps2::{F, f, f32s, fs};` (VU0 code: `use crate::vu0::{Vf, vf, v4};`), drop the
  `add/sub/mul/div/madd/msub/sqrt/lerp` imports, add `#![deny(clippy::float_arithmetic)]` after the module doc, and
  delete the module from both lists in `tests/float_math.rs`.
- Public fields and signatures stay `f32` (storage, serde, snapshots); wrap at the top of a function (`F(x)`,
  `fs(arr)`) and unwrap at the end (`.0`, `f32s(..)`).
- Keep every operation and its order exactly: `add(add(a, b), c)` → `a + b + c` (left to right, never regrouped);
  `add(a, add(b, c))` → `a + (b + c)`; `madd(acc, a, b)` → `acc.madd(a, b)` (keep the name where the original has a
  `madd.s`); `add(0.0, x)` → `F::ZERO + x` (it is not a no-op: −0 and denormals); `mul(x, -1.0)` → `x * -1.0`
  (rounds like a multiply; not `-x`). Unary `-` on an `F` is `neg.s`.
- Pitfalls: `f32 op f32` compiles silently as plain IEEE — the lint is what catches it (e.g. `atan2f(..) + p`,
  `CONST * x`): wrap one side in `F(..)`. Clippy flags unary minus on `f32` variables and consts but not on
  literals; use `-F(CONST)` or a `const NEG: f32 = -X;` (const bodies aren't linted). A local `f` variable shadows
  the `f()` helper: write `F(..)`.
- Where the old code used plain `f32` ops the original does on the FPU, switching to `F` changes rounding: check
  the decompile, note it in the journal, and let the hash trace decide.

## Proof: hashes unchanged

Before converting, record a baseline; after, record again and `cmp`:

```
HST_HASH_TRACE=$PWD/context/c2/base.txt tools/check.sh -p hst hash_trace -- --ignored                   # ~4 min
HST_HASH_GAMES=3 HST_HASH_TRACE=$PWD/context/c2/base3.txt tools/check.sh -p hst hash_trace -- --ignored
```

(`hash_trace` in `crates/hst/src/play/netplay.rs`: a mashed-pad bot match, per-tick `snapshot::state_hash`.) The
module's own tests and the replay fixtures (`tools/check.sh -p hst-sim`) must pass too. Presentation modules
(camera, cutaway, shade, effect, sound) may not feed the state hash: their `tests/` against recordings
(`camera`, `cutaway`, `shade`, `effect`, `sound`, `replay_camera`) are the check, and `tests/platforms.rs` runs
the match camera through `state_hash`.
