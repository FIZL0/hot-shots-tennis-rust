# B374 — Self-updater for the desktop builds (user 2026-10-14)

Linux (`dist/linux/hst`) and Windows (`dist/windows/hst.exe`) are single binaries, so an update is a file swap.
`reqwest` + `rustls` + `sha2` are already in `crates/hst`. The browser build updates itself and iOS can't, so this
covers desktop only (`#[cfg(not(target_arch = "wasm32"))]`, off on iOS).

## Check
- On start, in the background: `GET https://api.github.com/repos/FIZL0/opentennis/releases/latest`
  (send a `User-Agent`; no auth). Compare its `tag_name` (`v1.2.3` / `v0.1.0-alpha.N`) with
  `handshake::BUILD` / `CARGO_PKG_VERSION`, semver order, alpha < release. Only `v*` releases: the rolling `alpha`
  tag has no version, so a build from it doesn't get offered updates.
- No network, rate limit, or bad JSON → say nothing. Never blocks the menu or a match.
- Settings toggle "Check for updates" (default on); `--no-update-check` too.

## Offer
- Main menu: "Update available: vX → vY" row/badge; ✕ Update, ○ later (once per run). Any aspect ratio, legend.
- Lobby join refused for a version mismatch (`handshake.rs` "the game version") → the same offer if the host's
  version is newer and published.

## Install
1. Download the platform asset to `<exe dir>/hst.new` (`hst-linux-x86_64` / `hst-windows-x86_64.exe`), streamed,
   with a progress bar (as the mod installs do).
2. Download `SHA256SUMS` + `SHA256SUMS.sig`; check the minisign signature (`minisign-verify` crate, no deps) against the public key built into the game,
   then the file's sha256. Any mismatch → delete `hst.new`, show the error, keep the old binary.
3. Swap: Linux `chmod +x`, `rename(hst.new, current_exe)` (the running process keeps its inode). Windows rename
   `hst.exe` → `hst.exe.old`, `hst.new` → `hst.exe`; on start, delete a leftover `hst.exe.old`.
4. Relaunch with the same args (ISO path) and exit.
- Exe dir not writable (`/usr/bin`, Flatpak, Steam) → offer only a "Download page" link, no swap.

## Release side (`tools/release.sh`)
- Also upload the bare binaries `hst-linux-x86_64`, `hst-windows-x86_64.exe`, plus `SHA256SUMS` and
  `SHA256SUMS.sig` (signed with a key kept outside git, e.g. `~/.config/hst/release.key`; `release.sh` refuses to
  publish without it). Public key goes in the source.
- Key: `minisign -G -p ~/.config/hst/release.pub -s ~/.config/hst/release.key` (user, once); `release.sh` signs with
  `minisign -S -s ~/.config/hst/release.key -m SHA256SUMS -x SHA256SUMS.sig`; the `.pub` line is pasted into `update.rs`.

## Done when
- A test runs the check/compare/verify/swap path against a local file server (or files on disk): newer version
  swaps, bad signature/hash keeps the old binary, same version does nothing.
- By hand: an older Linux build and an older Windows build (wine is enough) update to a draft release and restart
  into the new version. Journal notes it.
