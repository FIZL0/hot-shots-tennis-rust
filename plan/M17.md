# M17 — browse and share user mods (user 2026-10-13)

Decisions and why. The task is the M17 line in `plan/TODO.md` (after M16, which installs a mod zip in the browser).

## Where mods live: a public Hugging Face dataset repo

No server of ours, no bill, nothing to keep running. The store is one public dataset repo on Hugging Face
(`FIZL0/opentennis-mods`, created by the user; the game reads its name from one constant):

```
mods/<id>/mod.zip        the mod as M16 imports it (mod.json + .glb files + voice/textures)
mods/<id>/meta.json      name, source game, author, version, size, sha256 of mod.zip, skeleton version
mods/<id>/preview.webp   the inspect bake (same framing as the select-screen previews)
```

Why Hugging Face (checked 2026-10-13):
- **Browser downloads work.** Downloads and the CDN they redirect to send `Access-Control-Allow-Origin`, tested on a
  548 MB file, so the web build can fetch mods directly. The tree listing
  (`https://huggingface.co/api/datasets/FIZL0/opentennis-mods/tree/main/mods`) sends it too.
- **Big files are fine.** A file can be up to 50 GB. Mods made with the mods repo's tools measured 0.3–590 MB (the
  Out of Bounds characters are 460–590 MB).
- **Uploads without our code.** Anyone with a free account can upload files on the repo's web page. For
  non-members it opens a pull request.
- **No approval step (user 2026-10-13).** Uploads go live as soon as the pull request is opened: Browse lists open
  pull requests as well as `main` (see *Browse mods*), so nobody has to merge anything. Taking a mod down means
  closing its pull request, or deleting `mods/<id>/` once it is on `main`. Reports go to the Community tab, and git
  history keeps the record.

Rejected:
- **GitHub Releases:** the asset download redirects to `release-assets.githubusercontent.com`, which sends no CORS
  header, so the browser can't fetch it (tested 2026-10-13). The API route ends at the same host, and anonymous use
  is limited to 60 requests an hour.
- **Mod files committed to a GitHub repo:** 100 MB per file and about 5 GB per repo, too small for 590 MB mods.
- **jsDelivr in front of GitHub:** small per-file limits, the same size problem.
- **Cloudflare R2 / S3:** needs a billing account and keys to manage, which is upkeep.
- **Peer to peer over iroh:** the uploader has to stay online for anyone to download.
- **archive.org:** the moderation isn't ours.

## Flows

**Upload my mod** (desktop and web):
1. Show the rules first: you're responsible for what you upload, so only share what you have the right to share.
2. Run the same checks as install: `mods::read` (skeleton, `mod.json` fields) and the size.
3. Write `mod.zip`, `meta.json` and `preview.webp`, into a folder on desktop or as downloads on web.
4. Open the repo's upload page in the browser (`https://huggingface.co/datasets/FIZL0/opentennis-mods/upload/main`). The player
   puts the three files under `mods/<id>/` and submits, which opens the PR. No upload code and no tokens in the game.

**Browse mods:**
- **Listing:** fetch the tree listing of `main`, plus every *open* pull request
  (`/api/datasets/FIZL0/opentennis-mods/discussions?type=pull_request&status=open`, paged), and each one's
  `mods/<id>/` at its `refs/pr/<n>` revision; files download from `resolve/refs%2Fpr%2F<n>/…`. Check that those PR
  URLs send CORS headers like `main` does, and pick a fallback if they don't. A PR whose `meta.json` or layout fails
  the checks is left off the list. If two entries share an `<id>`, `main` wins, then the newest PR. Then fetch each
  mod's `meta.json`. Cache the listing for an hour, on disk on
  desktop and in OPFS on web, to stay under anonymous rate limits. Load previews lazily as rows scroll into view.
- **Install:** download `mod.zip`, check its sha256 against `meta.json`, and run the full upload checks again on
  the player's machine. Then unpack into `mods/<id>/` on desktop or M16's OPFS store
  on web.
- **Verified badge (user 2026-10-13):** a mod on `main` (its PR was merged, i.e. approved by a maintainer) shows
  a "Verified" badge in Browse and on its installed entry; a mod listed only from an open PR shows none. Optional
  "Verified only" filter. The installed mod keeps the flag it had when installed and picks it up when its PR is merged.
- **Installed / Update:** store the zip's sha256 next to the installed mod and compare it with the listing.
- **Report:** opens a new discussion on the repo, prefilled with the mod id.

**My public mods (M19):** signed in, Upload my mod's second row lists the player's uploads (their open PRs by
author, and `main` mods whose `meta.json` author is their account, which Upload now writes there). ✕ twice closes a
PR, or opens a PR deleting `mods/<id>/` for a merged one (non-members can't commit to `main`).

**Maintainer:** nothing to do for a mod to go live. Close a PR, or delete `mods/<id>/` from `main`, to take a mod
down. Merging a PR approves the mod: it gets the Verified badge. With nobody reviewing, the *Mods are data only* checks on every
player's machine are what keep players safe.

## Limits

- **Storage:** Hugging Face's free public storage is best-effort. If the repo outgrows it, `meta.json` can carry a
  full URL so some mods live in a second repo. The game only needs the listing.
- **Accounts:** players need a Hugging Face account to upload. Browsing and installing need none.

## Game data in uploads (user decision 2026-10-13)

No game-data check, on upload or on install: what a player uploads is the uploader's responsibility, and the repo's
README says so. Extracted characters from other games are allowed in the store. Takedown requests go through
the repo's Community tab, and a maintainer deletes `mods/<id>/`.

## Mods are data only: no code, nothing malicious gets through (user 2026-10-13, applies to M16 and M17)

A mod is data the game reads: `mod.json`, `.glb`, textures, audio. Nothing in a mod is ever run, and no mod format
gets a scripting hook, plugin or shader. Every mod passes the same checks before anything is written, whether it
comes from a zip on desktop or web (M16), the Browse screen (M17) or an online lobby (`mods_online.rs`). Anything
that fails is rejected whole, with a message, and leaves nothing behind.

- **Archive:** an entry must be a plain file with a relative path that stays inside `mods/<id>/`. Reject absolute
  paths, `..`, symlinks, device names and duplicate names. Only allow the known extensions (`.json .glb .png .webp
  .tm2 .wav .ogg`, plus whatever the mod standard adds). There are caps on entry count, each file's size and the
  total unpacked size (compression-bomb guard), checked while unpacking, not trusted from the zip header.
- **Parsers:** `mod.json`, glTF/GLB, image and audio readers treat input as hostile. Bounds-checked lengths and
  counts (no allocation sized by an unchecked header field), errors instead of panics, and no unsafe code in them.
  glTF buffers and images must be embedded or relative inside the mod; external/`http`/`file`/`data:` URIs other
  than embedded data are refused.
- **Nothing followed:** URLs or paths in `mod.json` are never fetched or opened. Text (name, author) is
  length-capped and shown as plain text.
- **Downloads (M17):** HTTPS from the one store constant only. `mod.zip` must match the sha256 in `meta.json`
  before it is unpacked.
- **Proof:** a test set of bad mods (traversal, symlink, bomb, huge counts, truncated/garbage GLB and PNG, external
  URIs) that each must be rejected cleanly, and a fuzz run of the readers (`cargo fuzz`, or a seeded loop over
  random mutations) with no panics or runaway memory.
